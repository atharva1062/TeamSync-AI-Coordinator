PRD: AI Group Project Coordinator
Sponsored by Worcflow | Version 1.0 | Status: Draft
A Telegram bot that chases your teammates, understands their replies, and keeps the task board honest. It is a Python script plus SQLite, with no frontend framework and no build step.
1. The Pitch
Group projects stall because nobody wants to be the one who keeps chasing people, and boards only stay current if humans update them. This bot does the chasing and the updating, on a platform your team already uses.


Product
Telegram bot that follows up on tasks and updates a live board
For
College teams of 3 to 6 people, plus the coordinator who tracks them
Core promise
Reply in plain words (even Hinglish); the bot sorts it into progress, done, or blocked
Killer detail
"Connected, but waiting for test credentials" becomes Blocked, not Complete
Build style
One Python service, SQLite, Claude API. No Vite, React, or build step
Sponsor
Worcflow
2. How It Works
A reply never reaches the board directly. Claude classifies it first, and a blocker is saved with its reason.
3. What the Bot Understands
Every reply is sorted into one of four outcomes. The rule that earns the most marks: any open dependency means Blocked, even if work is done.
Reply
Status
Blocker saved
"Started on it"
In Progress
None
"Done, merged to main"
Complete
Cleared
"Connected, but waiting for test credentials"
Blocked
Waiting for test credentials
"Haan ho gaya, bas review baaki hai"
Blocked or In Progress (asks if unsure)
Review pending
"Will see"
No change; bot asks one question
None
The LLM returns strict JSON that the code validates before touching the database:
{
  "status": "Blocked",
  "blocker": "Waiting for test credentials",
  "progress_note": "API connection done",
  "confidence": 0.92
}
If confidence is under 0.6, the bot asks a clarifying question and leaves the record as it is.

8. Build Plan
Five phases, each ending with something you can show.
1. Setup: create the bot with BotFather, seed SQLite, make /start and /status work.
2. Messaging: /followup sends real messages; the reply handler receives them.
3. Brain: add the Claude classifier and update records plus history.
4. Polish: clarifying questions, dashboard page, error handling, test 20 sample replies.
5. Demo prep: one stretch feature, real teammates, screenshots, README, rehearsal.
9. Demo Script (5 minutes)
1. Show the board (30s): four tasks, owners, statuses.
2. Send follow-ups (60s): run /followup and show the real message landing on a teammate's phone.
3. Live reply (60s): the teammate types "connected, but waiting for test credentials".
4. Show the result (60s): task flips to Blocked with the blocker text, plus the history log row.
5. Run /status (45s): show the updated board and the dashboard.
6. Bonus (45s): a vague reply triggers a clarifying question, or show the risk report.
Evidence to capture: screenshots of the task list before and after, the real Telegram chat, the blocker detection, and the history table.
Backup plan: keep a recorded run, a second phone, and a mobile hotspot ready.
